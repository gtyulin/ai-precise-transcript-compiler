# AI 精準逐字稿編譯器

## 核心目標

將逐字稿視為待編譯的來源資料，而不是讓模型一次讀完後自由摘要。每一個實質講義主張都必須能回到原文位置；每一段原文也必須有「已納入、刻意排除、待判定」的狀態。這是來源保真與可稽核流程，不是自動聲稱達到研究上的理論飽和。

## 觸發與輸入

使用者要求「精準整理逐字稿」「不要漏掉」「做成講義／教材」「逐字稿編碼」「主題分析」或提供 `.txt`、`.md`、`.docx`、`.pdf`、`.srt`、`.vtt` 逐字稿時啟用。

開始前確認：來源檔、語言、講義用途、是否保留口語與案例細節、輸出格式及個資限制。若來源是掃描 PDF 或尚未轉錄的影音，先使用適合的轉檔／OCR 工具；本 Skill 不得假裝看過未成功讀取的內容。

## 不可違反的規則

1. 原文只讀：不覆寫、潤飾或偷偷修正原始逐字稿；疑似錯字另列疑點。
2. 不跳讀：每批只處理連續的一小段，預設 10 個意義單位或約 1,000–2,000 字，超出上下文就縮小批次。
3. 不把摘要當編碼：先建立意義單位，再抽象成概念、類別與主題。
4. 每項推論標籤化：`原文明示`、`原文重組`、`分析推論`、`待確認`；分析推論不得寫成講者原意。
5. 去重不刪證據：合併相近內容時保留所有來源位置、差異與反例。
6. 任一稽核失敗都不能報告「完成」；只能報告通過範圍與未決項目。
7. 含可辨識個案、學生、家長或敏感會議資料時，預設本機處理，輸出也要做必要的去識別化。

## 工作流程

### 0. 建立來源索引與預切割

保留原文副本並加上穩定位置 ID（例如 `T01-P003-L012`，依檔案可用段落、頁碼、行號或時間戳）。只做機械切割：說話者、段落、時間區間、頁面或固定字數；不可在此階段摘要或改寫。

建立 `source_index`：`source_id`、原始位置、文字雜湊（若可行）、字數、前後相鄰區塊與疑似缺漏。若原始檔有重疊轉錄、無法辨識處或時間跳躍，先標記，不得自行補全。

### 1. 意義單位與開放編碼

按原文順序逐批處理。每個意義單位應是「在目前研究／教學目的下具有一個完整意思的最小連續片段」，可跨句但不可脫離原文。每筆至少記錄：

```yaml
unit_id: MU-001
source_refs: [T01-P003-L012..L016]
verbatim_excerpt: "原文短摘；長內容保留在中間產物"
paraphrase: "只改寫語序，不增加內容"
open_codes: ["講者描述的行動或現象"]
evidence_level: explicit # explicit | reconstructed | inference | unresolved
uncertainty: null
```

若一句同時包含多個意思，拆成多筆並保留重疊來源；若只是贅詞、寒暄或技術性重複，標為 `context_only`，不要直接丟掉。

### 2. 批次完整性閘門

每批結束先停下來稽核，不得立刻跨批整合：

- 批次涵蓋的原文位置是否連續且無空洞？
- 每個文字區段是否至少對應一個意義單位，或有明確 `excluded_reason`？
- 摘錄是否真的存在於來源？
- 改寫是否添加講者沒有說的因果、評價或例子？
- 說話者、時間、否定語氣、條件與數字是否保留？

不通過就回到本批重做；不要用下一批的內容補洞。

### 3. 跨批整合與主軸編碼

只有所有批次通過後，才建立 `concept`。以「相同、相近、包含、延伸、矛盾、例示」分組；每次合併都保留 `member_unit_ids` 與合併理由。再從概念建立 `category`，最後建立 `theme` 或講義章節。不要因為分類漂亮就消除異質例子或反例。

### 4. 結構化合成

先寫結構表，再寫講義正文：

`意義單位 → 概念 → 類別 → 主題／章節 → 講義段落`

講義段落可重組順序，但每段附來源標記，例如 `[MU-001, MU-008]`。若為分析者補上的教學提示、定義、連接句或外部知識，使用獨立標籤與區塊，不混在講者內容中。使用者若未明確要求外部補充，預設不補充。

### 5. 雙向來源稽核

完成草稿後做兩輪獨立檢查：

**講義 → 原文：** 每個實質主張、數字、例子、因果與結論是否有來源？來源是否支持原句強度？找不到就刪除、降級為推論或標 `待確認`。

**原文 → 講義：** 每個意義單位的狀態是否為 `included`、`merged`、`context_only`、`excluded_with_reason` 或 `unresolved`？特別抽查批次邊界、否定句、重複但有新細節的段落、少數／反例與講者自我修正。

最後輸出稽核摘要：來源區段數、意義單位數、已納入數、合併數、刻意排除數、待確認數、無對應數，以及抽查失敗清單。無對應數大於 0 時，狀態只能是「未完成」。

## 建議中間產物

在可寫入的專案資料夾保存，不放入原始來源旁覆蓋它：

- `source_index.jsonl`：來源位置與完整性索引
- `meaning_units.jsonl`：逐批意義單位與開放編碼
- `batch_audits.jsonl`：每批通過／失敗與問題
- `concepts.jsonl`：跨批概念與來源成員
- `categories.jsonl`：主軸類別與合併理由
- `structure.yaml`：主題、章節、講義順序與來源 ID
- `handout_draft.md`：附來源標記的草稿
- `provenance_audit.json`：雙向稽核結果與未決項目

資料格式可因專案調整，但不得省略來源位置、證據層級與未決狀態。詳細欄位範本見 [references/intermediate-schemas.md](references/intermediate-schemas.md)。

## 回報格式

回報時用白話說明：目前完成哪一層、處理了多少來源、稽核是否通過、哪些內容尚未判定，以及下一步。不要把「已產出摘要」說成「已完成精準編譯」；只有雙向稽核通過且無未解來源缺口，才可稱為完成。
